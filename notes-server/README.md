# 远程 Markdown 笔记 API

配合花笺桌面端：Windows 托盘常驻，快捷键唤出远程便笺，直接编辑服务器原有 Markdown 文件。服务器不需要 Python、SSH 远程脚本或数据库。此服务与原有 `capture-server/`（固定文件追加收件箱）独立。

## 部署（Linux）

需要 Go 1.26，或使用下面的 Docker Compose。

```bash
cd notes-server
export NOTES_ROOT=/srv/markdown
export NOTES_TOKEN="$(openssl rand -hex 32)"
# 请妥善保存此 Token，桌面端连接时需要填写。
go run .
```

默认监听 `127.0.0.1:8789`。`NOTES_ROOT` 必须已存在，服务用户需要读写笔记目录的权限。

Docker Compose：

```bash
cd notes-server
cp compose.example.yaml compose.yaml
mkdir -p secrets
openssl rand -hex 32 > secrets/notes_token
chmod 600 secrets/notes_token
# 修改 compose.yaml 的 /srv/markdown 和 user（笔记目录所有者 UID:GID）。
# 确保容器中的该用户也有权读取 secrets/notes_token。
docker compose up -d --build
```

通过现有反向代理提供 HTTPS，例如 Caddy：

```caddyfile
notes.example.com {
    reverse_proxy 127.0.0.1:8789
}
```

私有网络可设置 `NOTES_BIND` 为对应监听地址。HTTP 会明文传输 Token 和笔记，仅用于本机或可信私有网络；公网使用 HTTPS。容器默认只发布到服务器回环地址。

| 配置               | 说明                                    |
| ------------------ | --------------------------------------- |
| `NOTES_ROOT`       | 现有 Markdown 笔记库目录，必填          |
| `NOTES_TOKEN`      | 至少 6 字符的访问令牌                   |
| `NOTES_TOKEN_FILE` | 从文件读取令牌，与 `NOTES_TOKEN` 二选一 |
| `NOTES_BIND`       | 默认 `127.0.0.1:8789`                   |

## 桌面端使用

1. 主窗口 → 应用设置 → **远程 Markdown 笔记库**。
2. 填写 API 地址与 Token。
3. 点击“保存并测试连接”，再启用“快捷键和托盘新建入口打开远程便笺”，保存设置。
4. 按原有全局快捷键（默认 `Ctrl+Space`）唤出远程便笺：每次都是全新空白便笺，与本地速记体验一致。

API 地址可以带反向代理前缀，例如 `https://example.com/notes/`；代理需移除该前缀后转发。Token 按 API 地址保存在操作系统凭据库，JSON 配置不保存 Token。HTTP 请求由 Rust 后端发送，不需要浏览器 CORS 配置。

- 空白便笺直接输入即可，自动保存（900ms 防抖）为服务器上的新 Markdown 文件；文件名按标题生成（如 `购物清单.md`），无标题用时间戳，重名自动加 `-2` 后缀。标题即文件首行 `# 标题`。
- “打开”标签页搜索、选择服务器上已有文件继续编辑；也可把便笺钉成桌面磁贴。
- 粘贴或拖放图片自动上传到笔记同级 `images/` 并插入相对链接；磁贴可按设置渲染 Markdown。
- 窗口重新获得焦点时，未修改的文件会自动从服务器刷新。
- 窗口关闭只是隐藏；下次唤起若上次内容尚未保存成功，草稿保留并提示。
- 网络失败或版本冲突时自动弹出合并界面：查看服务器版本，合并进草稿后“采用此基准保存”即可；期间服务器再次变化仍会提示冲突。
- 保存请求响应丢失后可重试，相同内容不会重复写入。
- 不同步笔记库，不把文件内容自动落盘到客户端。存在未保存草稿时应用退出会被拦截。
- 文本仅支持 UTF-8 `.md` / `.markdown`；最多 5000 个文件，单文件 2 MiB。不会创建笔记父目录，不支持删除、重命名、符号链接或图片以外的附件。

## 图片

编辑远程笔记时，可直接粘贴剪贴板图片或选择图片上传。支持 PNG、JPEG、GIF、静态 WebP、BMP，每张最大 20 MiB、4000 万像素；暂不支持 SVG 和动态 WebP。服务根据实际图片内容判断格式，不信任文件扩展名或上传的 `Content-Type`。读取时同样校验图片内容；GIF 校验首帧，保留完整原始文件与动画，不重新编码图片。

上传文件放在当前笔记同级的 `images/` 中，以内容的 SHA-256 命名，例如 `日记/images/abc….png`。便笺插入相对链接 `![图片](images/abc….png)`，因此 nvim、网页编辑器和其他 Markdown 阅读器仍可直接使用。同一目录下相同图片的重复上传会复用已有文件。原有笔记中的相对路径图片也可通过 API 读取，图片可以位于笔记库内其他目录。

图片上传成功就写入服务器，Markdown 正文仍需 `Ctrl+S` 保存。新建但尚未保存的笔记也可上传图片，前提是笔记父目录已存在。若上传后放弃草稿，图片仍会保留；服务不会自动删除可能被其他笔记共用的图片，无引用图片需手动清理。多张图片依次上传，部分失败时保留已插入的链接和原有正文。

## 协议

除 `GET /healthz` 外均需要 `Authorization: Bearer <token>`。

| 请求                                         | 响应                                                                                                   |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `GET /v1/files`                              | `{ "files": ["Inbox.md", "日记/今天.md"] }`                                                            |
| `GET /v1/file?path=Inbox.md`                 | `{ "content": "…", "revision": "\"sha256…\"" }`，同时返回 `ETag`                                       |
| `PUT /v1/file?path=Inbox.md`                 | 正文为原始 UTF-8 Markdown，返回 `{ "revision": "\"sha256…\"" }`                                        |
| `POST /v1/images?note=日记/今天.md`          | 正文为原始图片字节，返回 `{ "path": "日记/images/sha256….png", "markdownPath": "images/sha256….png" }` |
| `GET /v1/image?path=日记/images/sha256….png` | 原始图片字节，`Content-Type` 根据实际内容返回                                                          |

保存已有文件必须携带读取时返回的 `If-Match: "sha256…"`；新建使用 `If-None-Match: *`。版本冲突返回 `412`，缺少条件头返回 `428`，文件不存在返回 `404`。错误体为 `{ "code": "…", "message": "…" }`。

图片上传无需版本条件头，正文不是 multipart；图片上传与读取均要求同样的 Bearer Token。图片路径使用笔记库内的相对路径，查询参数需 URL 编码。内容无效或格式不支持返回 `415`，超过大小或像素限制返回 `413`，哈希命名位置已存在不同内容返回 `409`，非法路径返回 `400`。上传响应和安全重试均返回 `200`。图片地址不包含 Token，客户端通过已认证请求获取图片后显示。

## 保存与并发边界

服务在笔记库根目录上使用 `flock` 协调 API 写入；内容版本用 SHA-256 表示。保存先写入同目录临时文件，执行 `fsync` 后原子替换，保留原文件权限位；新文件为 `0600`。不会向 Markdown 正文添加元数据，也不会创建索引或数据库。

图片使用同目录临时文件、文件 `fsync`、原子硬链接创建和目录 `fsync`；不会覆盖已有文件，重复内容可安全重试。新图片权限为 `0600`，按需创建的 `images/` 目录为 `0700`。图片解码在每个服务进程中串行执行，限制大图并发解码所需内存。

其他编辑器不遵守 API 锁：保存前会检查版本，并在替换前再次检查，但检查与替换之间仍有极短竞争窗口。nvim / 网页编辑器也可能在之后保存自己的旧副本。因此避免在多个编辑器中同时修改同一文件；切换编辑器前保存并重新读取。服务应使用服务器本地文件系统；文件所有者是运行服务的用户，替换不保留额外 ACL/xattr。

路径访问使用 Go `os.Root` 限制在笔记库内，拒绝路径穿越、符号链接和非普通文件；文本接口仅允许 Markdown 文件，图片接口仅允许上述图片格式。服务不提供跨域访问许可、不记录笔记正文或 Token。目录不可同时用于存放不可信的设备文件或挂载点。
